# 债务与取舍登记分册（docs/debt/）

> 本目录是 `docs/architecture-rules.md` 第 8 节登记表的分册。第 8 节保留「条目 | 所属分册 | 一句话红线」的索引表；完整条目（状态、基线或上限、验证命令、红线）按关注域放在本目录。
> 本目录同时登记两类事项：已清除的违例与取舍已定的架构决定。后者不构成债务，登记目的是把取舍理由、上限与前提固定下来，避免被反复重提为待修项。

## 条目格式

每条固定四个字段：

- **状态**：`已修复`、`已统一`、`已接受`、`推进中`。`已修复` 与 `已统一` 记载已清除的结构性违例；`已接受` 表示取舍已定、不构成债务，条目只保留上限与前提；`推进中` 表示分期计划，按批次推进。
- **基线**：当前实测数值与统计口径，含不计入统计的例外。已修复条目保留基线作为回归锚点；已接受条目不设基线，改为写明上限。
- **验证命令**：可直接执行的命令，或指向 `docs/architecture-rules.md` 的对应小节；命令必须写清执行目录与排除规则。
- **红线**：触碰相关区域时必须遵守的约束。

## 维护纪律

1. **基线只减不增**：本纪律约束债务条目，任何改动使其基线恶化（新增违例文件、新增实例化点、新增重复代码）即判定违规；已接受条目改守其上限与前提，逾越上限或放弃前提同样判定违规。
2. **修复即登记**：修复一条债务须在同一变更内更新三处——本目录对应条目（状态与基线）、第 8 节索引表、`docs/architecture-rules.md` 第 9 节的分期状态。
3. **不得以提交信息替代登记**：条目状态只以本目录与第 8 节为准。
4. **新增条目**：先判断归属分册，按上述四字段写入对应文件，再补第 8 节索引行；无合适分册时新增分册并更新本文件的分组表。取舍条目须写明上限与前提，不得只写结论。
5. **验证命令必须实测**：写入前实际执行一次并确认输出与基线一致；执行目录或排除规则变化时必须写进条目，否则会产生假绿。
